= Deploy to OpenShift 
IMPORTANT: You will need a public container registry to store your image. If you don't have an account, we recommend you to create a free account at http://quay.io[window=_blank].

Our examples will be using the `quay.io` container registry and the `myrepo` organization, but you should change it to match your configuration.

== Adding the Kubernetes and Jib extensions

You need a container registry that is accessible from your Kubernetes cluster to deploy the application container image in it.

In this chapter we'll be using the Quarkus OpenShift Extension to create the OpenShift deployment file, and the Quarkus Jib Extension to create and push the container image to your container registry without the need of running local docker daemon.

== Adding the configuration properties

Add the following properties to your `application.properties` so that can push the container to correct location:

[.console-input]
[source,properties]
----
# Configuration file
# key = value
#quarkus.container-image.push=true # <1>

quarkus.container-image.registry=quay.io # <2>
quarkus.container-image.group=myrepo # <3>
quarkus.container-image.name=greeting-app # <4>
quarkus.container-image.tag=1.0-SNAPSHOT # <5>

quarkus.openshift.route.expose=true # <6>
quarkus.openshift.route.tls.termination=edge # <7>
quarkus.openshift.route.tls.insecure-edge-termination-policy=Redirect # <8>
----
<1> Push the image automatically when application is packaged.
<2> Registry where image is pushed. By default is docker hub.
<3> Group name of the container image.
<4> Container name. By default is the `artifactId` element of `pom.xml`.
<5> Tag of the container image. By default is the `version` element of `pom.xml`.
<6> Ask for OpenShift route configuration as well when the application is deployed.
<7> Terminate TLS at the OpenShift router, so the route is served over HTTPS.
<8> Send plain HTTP requests to the HTTPS address instead of serving them.

[NOTE]
====
With `edge` termination the router terminates TLS for you using the cluster's default wildcard
certificate. Traffic between the router and your pod stays plain HTTP on port 8080, so the
application needs no keystore, no certificate and no extra Quarkus HTTPS configuration.
The `Redirect` insecure-edge policy makes the router answer any `http://` request with a redirect
to the `https://` address rather than serving it in clear text.
====

[NOTE]
====
`quarkus.container-image.name` only renames the *image*. Everything else the extension generates —
`Service`, `Deployment`, `Route`, `ServiceAccount` — is named after the *application*, that is the
`artifactId` of your `pom.xml`. With the settings above you therefore push
`quay.io/myrepo/greeting-app:1.0-SNAPSHOT` but address the workload as `tutorial-app`.
====

IMPORTANT: Change `quay.io` to your container registry and `myrepo` to your organization.
If you don't, your push *will* fail.

== Authenticating and pushing the image to your container registry

In order to push the container image, you need to authenticate to your container registry:

[.console-input]
[source,bash]
----
podman login quay.io # or: docker login quay.io
----

Now create and push your container image using jib:

[.console-input]
[source,bash]
----
./mvnw clean package -Dquarkus.container-image.push=true
----

== Deploy your application to your OpenShift

When OpenShift extension is present in the classpath, a OpenShift deployment file is scaffolded for you during package phase.

[.console-input]
[source,bash]
----
oc apply -f target/kubernetes/openshift.yml
----

[.console-output]
[source,text]
----
serviceaccount/tutorial-app created
rolebinding.rbac.authorization.k8s.io/tutorial-app-view created
service/tutorial-app created
deployment.apps/tutorial-app created
route.route.openshift.io/tutorial-app created
----

[NOTE]
====
Earlier revisions of this tutorial produced a `DeploymentConfig` and an `ImageStream` here.
`DeploymentConfig` is deprecated since OpenShift 4.14, and because the image is pushed to an external
registry by Jib there is no `ImageStream` either: the extension now emits a plain `apps/v1`
`Deployment` that pulls `quay.io/myrepo/greeting-app:1.0-SNAPSHOT` directly.
====

You might need to wait for some seconds until your application is up and running:

[.console-input]
[source,bash]
----
oc rollout status deployment/tutorial-app
----

Access the service via the OpenShift route created automatically:

[.console-input]
[source,bash]
----
oc get route tutorial-app
----

[.console-output]
[source,text]
----
NAME           HOST/PORT                                                    PATH   SERVICES       PORT   TERMINATION     WILDCARD
tutorial-app   tutorial-app-nvinto-dev.apps.rm3.7wse.p1.openshiftapps.com          tutorial-app   http   edge/Redirect   None
----

The `TERMINATION` column shows `edge/Redirect`: TLS ends at the router and plain HTTP is redirected.

And check that the application answers:

[.console-input]
[source,bash]
----
export ROUTE_URL=https://$(oc get route tutorial-app -o jsonpath='{.spec.host}')
curl -s $ROUTE_URL/messages | jq
----

TIP: The route is HTTPS now, so use `https://` when you build the URL yourself. If you call the
`http://` address anyway the router answers `302 Found` with a `Location` header pointing at the
`https://` one — add `curl -L` to follow it.

TIP: You can build, push and deploy the container image in one go by running:
`./mvnw clean package -Dquarkus.openshift.deploy=true -Dquarkus.container-image.push=true`.
The property is `quarkus.openshift.deploy`, not `quarkus.kubernetes.deploy` — the latter is what the
Kubernetes extension uses and it is ignored by the OpenShift one.
